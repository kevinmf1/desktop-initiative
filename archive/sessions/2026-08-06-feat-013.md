## Things worth remembering

- **The token doubles as the manual code.** The data model gives Pairing Token a single secret, so a
  separate display code would be a second thing with its own expiry. Nine digits, grouped for
  reading, and a guess limit so the short code is not a brute-force oracle.
- **One slot beats a token table.** Overwriting the only slot on mint makes "refresh invalidates the
  previous" true by construction; a table of tokens with states would need a flag every future
  reader must remember to check.
- **`verify.sh` was the only gate that could run.** The screen sits behind Google sign-in, which
  still needs `GOOGLE_CLIENT_ID` / `TESTLAB_API_BASE_URL`, so the real component tree was driven in
  jsdom and the lifecycle covered in Rust. Same limitation as feat-009…012 — recorded, not glossed.
- **jest-dom is not set up in this repo.** `toBeInTheDocument` / `toHaveTextContent` throw *Invalid
  Chai property*; the existing tests use `toBeTruthy()` and `.textContent`. Match them.
